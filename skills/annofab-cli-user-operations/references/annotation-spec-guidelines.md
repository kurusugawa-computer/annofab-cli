# アノテーション仕様に関するガイドライン

## アノテーション仕様の変更方法
* できるだけ、変更内容に対応する専用コマンド（`annotation_specs add_labels`など）を用いて、アノテーション仕様を変更してください。
* 専用コマンドの実行回数を減らすことだけを理由に `annotation_specs import`を実行しないでください。


## アノテーション仕様を変更する際の共通のガイドライン 
### ショートカットキー
既存のショートカットキーと衝突しないようにするため、使用するキーは、キーボード上部1段目の数字キーと、キーボード上部2段目の`Q`~`P`に限定してください。
このキーに修飾キーを加えて、バリエーションを増やしてください。

### 英語名
ラベル、属性、選択肢の英語名は、アノテーションZIP内のJSONに出力されます。
したがって、アノテーションZIPを扱うスクリプトが扱いやすい名前にしてください。
たとえばスネークケースやキャメルケースにするなどです。


## ラベルの追加/変更

### ショートカットキー
ユーザーからの指示がなければ、ラベルにはキーボードショートカットを設定してください。
その際、できるだけラベルの順番とキーの順番が対応するようにしてください。

### `field_values`
https://annofab-cli.readthedocs.io/ja/latest/command_reference/annotation_specs/update_label_field_values.html#annotation-specs-field-values-samples を参照して、設定できる`field_values`があれば設定してください。

## 属性の追加/変更
* 属性を追加するには、先にラベルを追加する必要があります。

### 属性の種類の変更
アノテーション仕様で属性の種類を変更しただけでは、既存アノテーションの属性値が期待通りにならない場合があります。
たとえば、自由記述複数行（`text`）から自由記述1行（`comment`）に変更した直後は、アノテーションエディタ画面やダウンロードしたアノテーションZIPで属性値が空欄になる可能性があります。
その旨をユーザーに伝え、変更後に`annotation normalize_attribute_type`で属性値の型を現在のアノテーション仕様に合わせることを提案してください。
対応する変換や変換できない値の扱いは、[コマンドリファレンス](https://annofab-cli.readthedocs.io/ja/latest/command_reference/annotation/normalize_attribute_type.html)を参照してください。
実行する場合は、まず`--dry_run`で変更予定を確認し、更新はSKILL.mdの「リソースを変更するコマンド」に従ってユーザーの承認を得てから実行してください。

### 整数属性
* 小数を入力できません。小数を入力する場合は、属性の種類を「自由記述(1行)」にしてください。そして、正規表現による制約も設定してください。
* 未入力の場合、アノテーションZIPでは属性値が`0`になります。`0`と未入力を区別する必要があれば、属性の種類を「自由記述(1行)」にしてください。そして、正規表現による制約も設定してください。

### ラジオボタンとドロップダウンの使い分け
ドロップダウンとラジオボタンはどちらも「排他選択」で、アノテーションの出力結果は変わりません。アノテーションエディタ画面での入力方法が異なるだけです。
以下を考慮して、どちらにするかを決めてください。

* 任意入力か：ラジオボタンは一度選択すると未入力にできない。任意入力ならばドロップダウンにする。
* 選択肢に対してショートカットキーを設定するか？：ラジオボタンは選択肢に対して、ショートカットキーが設定可能。
* オートコンプリート：ドロップダウンは入力した文字列に部分一致した選択肢に絞り込むことができる。
* 選択肢の個数：選択肢が多ければドロップダウンがよい。





## 属性の制約の追加
* `annotation_specs add_attribute_restriction`コマンドに属性制約を表したJSONを指定して、アノテーション仕様に制約を追加します。
* 属性制約を表したJSONは、`annofabapi.util.attribute_restrictions`で生成してください。このライブラリを使うことで、使用できない制約（トラッキングID属性でのMatches（正規表現に一致する）など）のJSONを間違えて出力してしまうことを防げます。

```
>>> import annofabapi
>>> import json
>>> from annofabapi.util.attribute_restrictions import AttributeFactory
>>> service = annofabapi.build()
>>> annotation_specs, _ = service.api.get_annotation_specs("prj1", query_params={"v": "3"})

>>> fac = AttributeFactory(annotation_specs)

# 「'occluded'チェックボックスがONならば、'note'テキストボックスは空ではない」という制約
>>> restriction = fac.checkbox(attribute_name="occluded").checked().imply(fac.string_textbox(attribute_name="note").is_not_empty())

>>> print(json.dumps([restriction.to_dict()], ensure_ascii=False, indent=2))
[
  {
    "additional_data_definition_id": "9b05648d-1e16-4ea2-ab79-48907f5eed00",
    "condition": {
      "_type": "Imply",
      "premise": {
        "additional_data_definition_id": "2517f635-2269-4142-8ef4-16312b4cc9f7",
        "condition": {
          "_type": "Equals",
          "value": "true"
        }
      },
      "condition": {
        "_type": "NotEquals",
        "value": ""
      }
    }
  }
]
```

* 属性制約`matches`で指定された正規表現は部分一致でなく完全一致で評価されます。したがって、`^`と`$`は不要です。
* 属性同士の制約は、同じラベルに所属している属性同士で設けてください。異なるラベルに属する属性同士で制約を設けることはできますが、アノテーションエディタ画面で期待通りの挙動になりません。


## オプションの変更
* 動画プロジェクトの場合は、`annotation_specs update_option`で`{"can_overwrap": false}`を指定すべきかを検討してください。

## ラベルの削除
すでにアノテーションで利用されているラベルを削除すると、アノテーションエディタ画面では「存在しないラベルを参照している」という旨のエラーが表示されます。
それを解消するには、アノテーションエディタ画面でアノテーションを保存するか、`annotation delete_invalid_label_annotation`の実行が必要です。
その旨をユーザーに伝えて、必要ならば`annotation delete_invalid_label_annotation`の実行をユーザーに提案してください。

## 属性の削除
すでにアノテーションで利用されている属性を削除すると、アノテーションエディタ画面では「存在しない属性を参照している」という旨のエラーが表示されます。
それを解消するには、アノテーションエディタ画面でアノテーションを保存するか、`annotation delete_invalid_attribute_value`の実行が必要です。
その旨をユーザーに伝えて、必要ならば`annotation delete_invalid_attribute_value`の実行をユーザーに提案してください。


## アノテーション仕様のチェック
ユーザーから指定された「アノテーションルール」と「レビュー観点」に基づいてレビューしてください。

### デフォルトのレビュー観点
ユーザーからレビュー観点を指定されなければ、以下の観点に従ってレビューしてください。

* 名前
    * 英語名と日本語名に誤字脱字がないか
    * 英語名と日本語名が対応しているか。ベトナム語名は基本的に利用しないので、チェック不要です。
    * 英語名はアノテーションJSONに出力されたときに、スクリプトで扱いやすい名前になっているか
* ショートカットキー
    * 既存のショートカットキーとの衝突を防ぐため、キーボード上部1段目の数字キーと、キーボード上部2段目の`Q`~`P`に限定されているか
* ラベルの色
    * ラベル名に「信号の青色」などの色情報が記載されている場合、ラベルの`color`情報はラベル名に対応しているか
    * 異なるラベルで似た色が使われていないか。ただしラベルの個数が多い場合は、色の衝突は避けられないので指摘しない。
* 属性
    * 適切な属性の制約が設けられているか
    * 空文字と`0`を区別する必要がある属性で、属性の種類が「整数」になっていないか
 
  
以下の場合は指摘が不要です。
* 日本語名に英語名が記載されているなど、言語と名前が対応しない場合。名前を翻訳する手間を省くため、そのように設定することがあるためです。
